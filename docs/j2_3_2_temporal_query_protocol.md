# J2.3.2 时间查询协议（P0-D 修复）

日期：2026-11-05 | 独立确认：oracle 路径 + 412 强制注入 + gap 727/709/85

## 1. 缺陷确认

`build_tiered_negatives_v2.py` 用 `m['target_frame']`（**真主未来
重现帧——监督标签**）作候选搜索窗口中心，并单独强制追加真主：
412/412 anchor 全含真主（无自然 no-match）、窗口生成依赖 oracle
时刻。绝对分布：440 行恰在 target 帧、2,767 行在 ±11——池形状
由答案时刻决定。

## 2. 修复协议（固定时间查询——任务 §四指定优先）

- **query_time = anchor_end + 1.0s**（**预注册协议常量**：取正对
  gap 分布中位——设计选择，非任何评价集调参）；
- 候选池 = query 窗 [±0.4s] 内**可观测**身份（存在性扫描，
  anchor 自身身份不经特殊路径——自然重现才在池内）；
- **标签事后粘贴**（is_true_match）；`true_target_frame` 保留为
  纯监督列；
- 结果：3,597 候选行（Tier-1 2,072 / Tier-2 1,113 / 真主 412）；
  412/412 自然含真主——**no-match=0**（诚实记录：JAAD 插值连续
  标注使真主在任意 1.0s 窗内几乎总有观测；真实施训遮挡场景
  不存在于本数据）。

## 3. 协议边界（固定时域 vs 开放时域，任务 §四.6）

- **本轮协议 = 固定时间查询**（受控再识别实验：查询时刻由协议
  预设）；**不得描述为部署式未知重现时刻的在线关联**——后者需
  检测触发的 query_time（后续阶段）；
- Gap 分层：固定查询下候选 delta_s ∈ [0.6, 1.4]s（中位 0.6）——
  旧 15/30/45 帧设计不再适用，报告改为 query 邻域单层（诚实）。
