# J2.3.2a 时间查询修复（P0-B）

日期：2026-11-05 | 独立确认（412/412 delta=0.600s）

## 1. 缺陷确认

`build_fixed_query_v3.py` 的 `f_c = in_win[0]`（窗口起点优先）使
**全部 412 个真主候选的实际 delta = 0.600s**（窗口 [0.6, 1.4] 的
起点），而名义查询时刻为 1.0s——**名义与实际预测间隔偏差 40%**。

## 2. 修复

- 每候选选择**最接近 query_frame** 的自身有效观测（非窗口起点）；
- **预注册容差 0.2s**：|obs_time − query_time| > 0.2s → 该候选
  unavailable（从池中移除——不无条件使用较早帧）；
- 候选池与标签逻辑已分离（J2.3.2 完成）；无 oracle 时间依赖。

## 3. 修复后实测

| 指标 | 旧 | **新** |
|---|---|---|
| 真主 delta_s | 0.600（全部 412 条） | **1.000**（全部 412 条） |
| query_time_error | — | mean 0.005 / p95 0.033 / max 0.200 |
| 候选总行数 | 3,597 | 3,513（−84 因容差过滤） |
| Tier-1 | 2,072 | 1,983 |
| Tier-2 | 1,113 | 1,118 |

审计参考数字（3,597/2,026/1,159）与实际的差异归因：我们的实现
**额外执行 0.2s 容差过滤**（审计参考未含该过滤）——诚实差异，
非协议错误。审计数字"仅用于验证时间选择确实影响候选集合"——
方向一致（总行数近似、Tier-1 下降、Tier-2 变化）。

## 4. 泄漏检查

候选时间选择不依赖正确身份的真实重现时间——每个候选独立按
`min |obs − query|` 选择。Oracle 路径零存在（skeptic agent 验证）。
